# 回收站版本升级与回退

面向部署维护者；前置知识为现有存储迁移流程。此页只说明新增生命周期带来的兼容约束。

## 发布与回退

1. 固定本次提交构建API/worker/web，记录镜像与测试证据。
2. 停止旧API/worker写入，执行既有存储迁移流程；knowledge v1依次v2/v3，v2升级v3，新库直接v3；business v7升级v8，只增加个人回收journal，新库直接v8。
3. 同步切换API/worker/web，验证权限、删除、恢复、下载隔离及worker日志后开放。
4. 不将未识别deleted_at的旧版本直接回滚上线：会重新暴露回收站内容。故障时先停清理worker并保留数据库，回退到仍有过滤逻辑的修复版本。

当前生产发布与永久清理启用需单独审阅确认。测试文件只在独立验收环境生成。已发送给用户/模型的历史聊天内容及用户主动保存的独立记忆不自动擦除；知识库回收阻断删除源的新读取，不承诺撤回历史回答。个人文件同时对可能含删除资料的旧会话实施保守模型发送隔离（详情见使用页），但不删除原聊天或独立记忆。
