# 0.8.1 候选更新说明

当前候选为 `v0.8.1.beta2`。本页记录 0.8.1 主线相对正式 `v0.8.0` 的变化。已发布的 `v0.8.1.beta1` 使用[标签内的升级说明](https://github.com/xerrors/Yuxi/blob/v0.8.1.beta1/docs/develop-guides/releases/0.8.1.md)。CLI 沿用独立版本。

## 使用上的变化

- **插件与连接器**　智能体可按需加载知识库和 aBridge 插件。对话中可提及连接器或设备，单个连接暂时不可用时，其他可用连接仍可工作。Skill 保留内容和脚本，运行能力由插件声明。见[插件开发](../../agents/plugin-development.md)。
- **知识检索**　支持从多个知识库检索并阅读来源原文。评估可识别已失效的参考块，删除评估会取消关联后台作业。RapidOCR 限制 CPU 推理线程数。
- **身份与设备**　本地账号支持自助修改密码。可选 OIDC 身份签发与 aBridge 集成支持个人设备，启用托管浏览器还需支持登记接口的 aBridge Server、配套浏览器发行物和 Cube 节点模板。见[aBridge 接入](../../advanced/abridge.md)。
- **会话与协作**　历史消息可独立加载。侧栏分别浏览会话工作区和个人空间，已有会话按自身配置和当前权限显示可引用资源。优化工具时间线和文件面板轮询，支持从调试窗口导出 Turn。协作默认允许一层子会话，每棵树默认并发 12、上限 20，等待和取消按实际轮次显示。兼容模型可展示推理内容并在续答时保留供应商需要的原文。
- **文件与预览**　个人空间提供最近打开的文件、近期交付物、完整项目目录和用量。Office 文件由浏览器预览原件，渲染失败时可以下载原件。达到软配额时暂停文件上传和新任务启动，已提交的输入可继续排队，正在执行的任务可完成。删除会话工作目录后仍可查看历史，恢复原路径后可继续会话。
- **管理**　独立的系统管理入口集中供应商、API 集成、用户、部门、系统概览和智能体反馈。用户和部门管理支持批量删除并逐项报告结果。共享权限选择支持服务端搜索，已删除智能体的历史活动仍计入统计。
- **运维**　远程 Skill 安装支持在没有聊天 Run 时获取，内置 Skill 首次同步修正默认读取权限。Container 部署须[更新沙盒镜像及其 digest](../../advanced/container-sandbox.md#远程-skill-获取)。支持只读诊断 PostgreSQL 空闲事务的来源。

## 从正式 0.8.0 升级

| 范围 | 升级结果 |
| --- | --- |
| PostgreSQL | 按[数据库升级顺序](../../advanced/deployment.md#_3-数据库与文件目录)离线执行 business 2 → 5 → 6 → 7 → 8，knowledge 保持 2。 |
| Public v1 产物预览 | `preview=true` 对 DOCX、PPTX、XLSX、XLS 返回 Office 原件及对应 MIME。使用方可按响应头选择渲染或保存。[产物预览](../../advanced/agents-public-api.md) |
| Skill 与 MCP | 转换 Agent 配置、会话快照与受影响 Skill 的当前包，删除旧依赖列并记录代码发布的连接归属。旧 Skill 激活时附带的通用工具授权取消，原有工具选择保留。若业务依赖这些工具，需显式补选。自定义部署还需审阅来源和能力范围。 |
| 运行记录 | 迁移保留既有消息、Input 和 Run。新 worker 在启动清扫及后续运行中按线程和命名空间保留最近 5 个 checkpoint，跳过有活动 Run 的线程；已失去会话的旧 checkpoint 有 7 天宽限期。 |
| 运维 | PostgreSQL 新会话及日志使用 UTC，历史时间值保持原值。若旧消息的 JSON 含 NUL 并影响读取，可单独运行 `python -m yuxi.migrations.json_nul_repair`，回读受影响消息并核对 `failed_ids`。 |

先排空并停写，备份同一时点的数据库与文件，使用目标镜像导出、审阅并应用[插件迁移](../../agents/skills-management.md#从运行依赖升级)，再完成[后续数据库迁移](../../advanced/deployment.md#会话状态迁移)。回读版本和业务数据，重跑 app-init，再启动 API 和 worker。回退需恢复配套的旧版本与备份。全新部署直接初始化目标基线。

已完成初始化的 `v0.8.1.beta1` 从 business 5 / knowledge 2 起步。按[数据库升级顺序](../../advanced/deployment.md#_3-数据库与文件目录)停写并备份后，直接执行会话状态、最近文件和用量迁移，再回读数据并恢复服务。

维护者可查阅[架构沿革与清理评估](./0.8.1-history.md)，了解升级起点和仍有消费者的历史路径。
