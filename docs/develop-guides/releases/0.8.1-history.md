# 0.8.1 候选的架构沿革与清理评估

本次核对从 2024 年的首个提交追到 `f3db10cac`。该提交有 3,131 个可达提交，自正式 `v0.8.0` 起有 65 个提交。下表以发行标签、改变行为的提交和该提交之后的调用方为依据。仓库内的调用关系只能证明本仓库的使用情况。

## 哪些设计仍解决实际问题

| 阶段 | 架构变化 | 今天仍需要的边界 |
| --- | --- | --- |
| 2024 原型至 0.3 | 首个版本把浏览器提交的历史传给模型；随后加 RAG、Compose、FastAPI 和 Tasker。见[首次提交](https://github.com/xerrors/Yuxi/commit/9d6f9e35e)、[早期 RAG](https://github.com/xerrors/Yuxi/commit/b9d6d13d7)和 [FastAPI 合并](https://github.com/xerrors/Yuxi/pull/11)。 | 请求可以结束在后台任务之前。当前产品用持久任务状态支持进度读取、取消和重启恢复。 |
| 0.4 至 0.6 | 知识元数据、账号/对话和任务分批转入 PostgreSQL，后来才迁移 LangGraph 的执行状态。见[知识元数据](https://github.com/xerrors/Yuxi/commit/1665fbd6e)、[用户和对话](https://github.com/xerrors/Yuxi/commit/c1ab585f7)、[任务](https://github.com/xerrors/Yuxi/commit/4672bdbe2)。 | 业务历史和可恢复的图状态有不同的读取者与保留期限。知识库中的元数据、对象和向量索引也有不同的存储职责，备份要覆盖整套状态。 |
| 0.7 系列 | SQLite saver 的 WAL 曾缓解并发问题。后续 checkpoint 转入 PostgreSQL，共享工作区与沙盒文件边界明确；Input 排队和后台作业租约分别解决消息顺序与执行者失联。见 [PR #894](https://github.com/xerrors/Yuxi/pull/894)、[PR #915](https://github.com/xerrors/Yuxi/pull/915)、[PR #969](https://github.com/xerrors/Yuxi/pull/969)和[作业租约](https://github.com/xerrors/Yuxi/commit/9f139ab1e)。 | PostgreSQL 保存执行归属和可恢复状态，Redis/ARQ 在事务提交后投递工作。用户文件、对象 URL 和 Run 的虚拟路径分别在拥有它们的文件系统内校验。 |
| 0.8.0 | Session 成为对外会话概念，Thread 继续标识执行上下文。普通提交先保存 Input 和 Receipt，消费事务再建立 Message、Turn 和 Run。权限在资源读取与执行时复核。见[会话重命名](https://github.com/xerrors/Yuxi/commit/578c6d454)、[消费投影](https://github.com/xerrors/Yuxi/commit/c373d2298)和[共享权限](https://github.com/xerrors/Yuxi/commit/0eebb05a0)。 | 一个提交可以排队或取消，一个 Turn 也可以在审批恢复后拥有多个 Run。把这几种身份合并会破坏 FIFO、恢复或结果归属。前端权限检查承担交互反馈，后端承担授权。 |
| 0.8.1 候选 | Knowledge 和 aBridge 连接按插件激活；知识库对外 MCP 与读取授权继续由知识域负责。`/state` 提前释放读事务，worker 裁剪超过策略的 checkpoint 历史。见 [PR #1193](https://github.com/xerrors/Yuxi/pull/1193)、[PR #1172](https://github.com/xerrors/Yuxi/pull/1172)和 [PR #1173](https://github.com/xerrors/Yuxi/pull/1173)。 | 插件选择影响智能体获得的工具，知识读取仍按当前用户和会话选库检查。升级后的旧 Skill 插件声明仍由部署加载，已经迁过的站点继续依赖它。消息和 Run 的历史读取独立于 checkpoint 裁剪。 |

## 哪些历史路径可以退出

**本候选已收敛的发行路径。** 正式 0.8.0 已有个人 MCP 凭证列与知识目录约束，直接升级无需补列或实体化目录。business 4 只出现在两个主线提交之间。旧工具仍可随旧标签运行；候选把精确的 2/2 升级到 5/2。操作与数据影响见[数据库升级决定](../decisions/implemented/2026-11-25-release-database-upgrade.md)。

候选版还移除了以下四组内部入口。它们原来负责的用户行为已有实际调用路径和验证入口。

| 已移除的入口 | 原用途及失去调用方的原因 | 当前行为与验证入口 |
| --- | --- | --- |
| 前端 `STATUS_SORT_ORDER` 和 `getFileStatusSortWeight` | [前端排序](https://github.com/xerrors/Yuxi/commit/391c28652)服务于已加载的一页。改为[服务端排序](https://github.com/xerrors/Yuxi/commit/ea19d0202)后，表格发送排序条件，repository 在分页前排序。 | 文件列表 API 集成测试核对跨页顺序、未知状态和相同排序键的次序。见[文件列表排序决定](../decisions/implemented/2026-11-10-knowledge-file-list-sort.md)。 |
| 前端 `checkAdminPermission` | [代码组织调整](https://github.com/xerrors/Yuxi/commit/61b4e5ef2)后，请求使用 `assertApiAdminPermission`。身份模块的公开入口也未导出旧函数。 | API 客户端提示权限不足。调试组件仍检查 superadmin，后端依赖仍负责资源授权。 |
| `EvaluationRepository.update_run` 的自建事务包装 | [后台作业租约](https://github.com/xerrors/Yuxi/commit/9f139ab1e)把结果写入移到拥有执行权的事务。独立事务包装和对应的测试替身失去调用方。 | 评估在 `run_owned_transaction` 内调用 `update_run_in_session`，由作业租约和取消测试验证写入边界。 |
| MCP 的 `get_enabled_mcp_server_config` 和 `get_enabled_mcp_tools` | 单服务包装曾用于 [API 与 worker 共享配置读取](https://github.com/xerrors/Yuxi/commit/6df070ddb)。[知识域装配调整](https://github.com/xerrors/Yuxi/commit/e01304a01)后，运行时按实际选中的服务列表解析工具，两个包装只被测试调用。 | 配置测试回读服务记录，OAuth 和静态凭证集成测试通过运行时的工具解析入口核对当前用户实际可调用的工具。 |

**仍有消费者的历史能力。** 旧 LITE 运行模式已经移除。当前关闭 Knowledge 的部署契约覆盖路由、能力发现、worker 装配和保留中的数据。Dashboard 的 SQLite 日期分组仍被真实 SQL 单测调用，移除前要为相同语义补上 PostgreSQL 证据。已经停产的工具仍可能出现在用户的历史消息中，删除渲染器前需要核对已发布的数据格式、通用渲染结果和外部客户端。见[LITE 移除提交](https://github.com/xerrors/Yuxi/commit/44ecd6791)、[当前部署契约](../../advanced/deployment.md#可选关闭知识库)和[统计测试](https://github.com/xerrors/Yuxi/blob/main/backend/test/unit/services/test_dashboard_user_activity_agents.py)。
