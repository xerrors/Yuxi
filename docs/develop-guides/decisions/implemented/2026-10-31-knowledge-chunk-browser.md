# 知识文件分块查看与编辑定位

状态：implemented
类型：bug-fix
Owner：frontend/src/modules/knowledge/ui/FileDetailModal.vue

## 问题

知识库管理者需要读取每个分块的完整内容，判断 HTML 表格等内容的截断位置。卡片摘要无法完成该任务，完全重叠的分块还可能被合并逻辑省略。页面保存的编辑意图会让后续阅读再次进入编辑态。

目标是搜索、选择、完整阅读分块并跳到全文编辑位置；不新增分块级保存，不改变解析、入库、权限或保存作业。

## 决策

### 实现方案

知识域的分块浏览组件按顺序展示接口返回的全部原始分块，左侧按文本或 chunk_id 即时筛选，右侧复用源码预览展示完整内容，保留 HTML 标签与截断边界。搜索无匹配、无分块、加载中与读取错误分别反馈。

文件详情继续拥有编辑准入和严格全文读取；分块编辑入口传入 start_line，没有有效行号时传入 1。共享文件编辑器负责光标与滚动定位，适配换行显示。页面通过双向属性消费一次性的编辑请求，避免取消、关闭或换文件后继承意图。桌面与紧凑下拉菜单都将“编辑文件”独立分组；表格入口使用相同名称。

## 替代方案

- 保留卡片并增加展开：难以连续对比分块，且不满足用户指定的左右布局。
- 直接编辑单个 chunk：增加保存语义与索引一致性责任，用户明确要求跳到现有全文编辑器。
- 通过文本搜索推算行号：重复文本和截断表格不能可靠定位；缺失行号时直接到开头。

## 后果

分块列表与预览直接使用原始内容，完整保留重叠块；全文预览仍沿用原有合并回退逻辑。分块按源码展示，方便观察 HTML 标签和截断边界。编辑保存继续作用于整个解析文件，保存后的重新入库与构图要求保持原有语义。

一次性的编辑意图由知识库页面与详情组件通过双向属性交接，不依赖关闭动画结束后才清理。共享编辑器使用浏览器规范化后的 textarea 值计算行偏移，由浏览器在焦点进入时滚动到光标，支持自动换行。
