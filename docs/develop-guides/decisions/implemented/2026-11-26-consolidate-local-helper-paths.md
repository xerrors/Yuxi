# 收敛闲置前端封装与重复配置读取

状态：implemented
类型：simplification
Owner：frontend/src/modules/identity/model/user.js

## 问题

用户管理直接使用服务端分页，前端 Store 和 API 客户端曾保留逐页拉取全量用户的入口。会话布局的全局样式包含浏览器无法解析的 `:deep()` 选择器，消息引用栏单独处理复制。系统测试的镜像构建脚本为四个镜像重复解析同一份 Compose 配置。

## 决策

### 实现方案

用户管理页继续使用 `authApi.getUsersPage`，删除前端全量列表封装。`SessionWorkspace.vue` 移除两条无效规则。`RefsComponent.vue` 复用共享剪贴板工具，在工具确认写入后显示成功，失败时给出错误提示。

`scripts/ci/build_topology_images.sh` 从一次 Compose 读取中解析当前模式所需的镜像名。配置缺失时先失败，完整配置沿用现有镜像构建顺序和缓存。

## 替代方案

保留全量列表可供未来调用，但当前页面直接使用服务端筛选和分页。修改 `:deep()` 使其生效会新增现有布局没有应用的样式。各调用点分别处理复制或配置解析会继续维护重复路径。

## 后果

用户管理继续使用分页 API。非安全上下文复制沿用共享工具的降级路径。仅构建 sandbox 时只要求 sandbox 镜像名。

## 验证

- 前端 API、表单和复制回归通过。旧消息复制在写入失败时显示成功，新增用例在旧实现上按此原因失败。
- Vite 原样输出全局样式中的两个旧选择器。Chromium CSSOM 丢弃两条规则，并保留有效对照选择器。现有协作回放在基线和候选均因插件列表夹具缺失而超时。临时夹具补齐数组响应后，Chromium 验证 1440、1024、768px 的会话侧栏、最大化切换和浏览器前进后退。
- 用真实 Bash 和 jq 验证全拓扑、sandbox-only 和缺失镜像场景。每种场景只读取一次 Compose；缺失所需镜像时不开始构建。
- 旧能力不存在：前端全量用户列表封装、无效样式、引用栏独立复制和重复读取 Compose 配置均退役。
- 重新引入条件：可指认的调用方需要现有分页或共享能力无法提供的行为。
