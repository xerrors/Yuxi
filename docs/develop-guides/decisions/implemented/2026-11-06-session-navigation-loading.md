# 会话导航的首次加载状态

状态：implemented
类型：bug-fix
Owner：frontend/src/modules/session/model/chatThreads.js

## 问题

侧栏的项目和对话列表分别读取。只使用项目的加载状态会在对话尚未返回时显示空历史和加载更多。

## 决策

### 实现方案

会话 Store 记录当前用户的首次列表读取是否成功及失败状态，并在用户切换时清空列表和分页状态；旧用户的列表读取、分页及 Store 内的异步更新结果不能更新当前列表。会话工作区补充读取会话详情时也核对发起账号，回填当前会话前还要核对会话 ID。侧栏与搜索只在当前列表首次读取成功后使用列表，账号切换时关闭搜索弹窗。项目与对话列表不等待智能体初始化即可开始读取，侧栏在项目或对话尚未就绪时显示骨架，对话读取失败时提供重试，收起“最近”后仍可重试；空历史和加载更多只在列表结果已知时展示。项目和对话继续分别使用各自的读取入口和错误状态。

## 替代方案

- 继续只依据项目加载状态：无法覆盖两个请求完成顺序不同的情况。
- 以固定延时显示骨架：不能反映真实请求完成或失败。

## 后果

首次进入侧栏时，骨架持续到列表实际返回；已有列表的后续刷新保留现有内容。首次读取失败可以重试。

## 验证

按用户要求未运行测试或浏览器验证；项目和对话先后完成、失败重试及账号切换的页面行为尚未验证。
