# 以正式 0.8.0 为升级起点收敛兼容

状态：implemented
类型：simplification
Owner：backend/yuxi/bootstrap/options.py

## 问题

正式 0.8.0 的 app-init 已转换 MinerU 档位并清理退役的 OCR 配置。为更早的试用状态在每次初始化重复执行转换，会在受支持的升级路径上保留额外的数据库读写。项目目录请求、知识文件排序与 Skill 依赖拆分也留下了已失去消费者的内部入口。

## 决策

### 实现方案

启动同步发布现有 OCR 配置定义，保留管理员保存的服务地址、档位和凭据。旧 OCR 数据转换随正式 0.8.0 的源码发布。受支持的[部署升级](../../../advanced/deployment.md#_3-数据库与文件目录)从已初始化的 2/2 开始，依次执行插件和会话状态迁移。5/2 是同一次升级的续跑点。

正式版能读取和保存的数据仍沿原有读取路径处理，包括知识文件状态、已绑定的旧 Workdir 和历史消息。配置同步继续清除 aBridge 已退役的凭据，以防字段定义移除后配置接口返回其原值。

工作区页面读取普通目录接口。知识文件的日期顺序由 repository 在分页前决定。连接器测试直接核对可配置服务和实际运行可用性。

## 替代方案

保留启动转换会继续照顾未纳入升级承诺的试用配置。仅凭结构版本拒绝所有 5/2 数据库会阻断正式升级的续跑。重写正式版可以正常读取的数据会增加持久影响，且无法缩小据此承担的读取契约。

## 后果

过渡部署应按其匹配的代码和成套备份处理。数据库版本只记录结构，部署者按发行标签核对起点。容许正式版已有的历史读取格式，减少的是升级与初始化入口。

## 验证

使用正式标签源码在独立 PostgreSQL 建库并保存 MinerU 和 PaddleOCR 设置。通过两个现有离线命令回读 2/2、5/2 和 6/2，并比较 app-init 后的配置原值与修改者。定向回归覆盖启动同步、权限、文件排序与目录选择。

旧能力不存在：生产源码不再包含旧目录参数透传、`compareFileCreatedAt`、`get_enabled_mcp_server_slugs` 或启动 OCR 转换。配置目录的 HTTP 用例验证退役项不会出现在配置与引擎列表。

重新引入条件：存在支持升级的正式起点及可复现的实际消费路径。
