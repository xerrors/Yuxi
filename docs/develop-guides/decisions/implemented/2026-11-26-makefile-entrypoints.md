# 收敛 Makefile 开发入口

状态：implemented
类型：simplification
Owner：Makefile

## 问题

`reset` 将默认 Compose 状态目录删除和固定密码测试账号创建绑定到同一个入口。快速开始和 CI 各自通过应用的初始化入口创建管理员。`verify-trust` 重复封装现有工程检查，现行文档和工作流直接运行检查命令。

## 决策

### 实现方案

Makefile 保留现行开发文档和问题模板使用的启动、日志、格式化、lint、单测和审计目标，以及配套的停机目标。快速开始使用网页完成管理员初始化，CI 使用初始化接口。旧造数脚本随[闲置开发入口清理](./2026-11-26-retire-unused-development-entrypoints.md)退役。工程契约与版本验证的命令由各自的脚本和工作流维护。

## 替代方案

保留 `reset` 并修复就绪等待，可继续提供一键清库造数，但没有已知的仓库调用者。移除整个 Makefile 会让贡献指南、问题模板和本地审计失去现有的简短入口。

## 后果

仓库外调用 `reset`、`seed` 或 `verify-trust` 的脚本需要改用现有入口。开发者可通过独立状态目录启动全新环境。

## 验证

- 逐项比对变更前后的 `make -n` 输出。默认入口、八个保留目标、Compose 覆盖和测试参数覆盖共 11 组结果一致。
- 旧能力不存在：`make -n reset`、`make -n seed` 和 `make -n verify-trust` 均因目标不存在而失败，退出码为 2。
- 重新引入条件：可指认的重复工作流依赖对应目标，现有入口无法满足该流程。
