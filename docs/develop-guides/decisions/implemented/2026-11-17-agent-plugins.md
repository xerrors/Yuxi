# 插件能力边界、运行装配与首次升级

状态：implemented
类型：architecture
Owner：backend/yuxi/modules/extensions/plugins/registry.py

## 问题

知识库和设备操作需要同时交付说明、工具、连接及权限约束。把运行依赖放入 Skill，会让读取说明同时改变能力；把插件直接实现为完整框架中间件，又需要逐项禁止修改图结构和恢复状态。图像等纯说明功能不需要承担插件激活状态。

开发者需要在一个目录交付完整功能，用户需要明确的能力开关。生产环境尚无已发布插件，只需安全转换旧 Skill 依赖和会话配置，无需维护改造中间版本。本文为维护者记录这些边界的取舍；开发步骤见[开发插件](../../../agents/plugin-development.md)，运行行为见[Agent 运行机制](../../../mechanisms/agent-runtime.md#插件激活与恢复)。

## 决策

### 实现方案

插件随部署发布，以明确 ID 列表配置；新增部署插件不会自动扩大已有智能体的能力。每个插件目录包含 `plugin.py` 和配套 `skills/`，`REGISTERED_PLUGINS` 显式登记类及装配顺序。新增业务插件使用 Python 类；历史 Skill 依赖转换出的 JSON 部署声明保留已有读取入口。

`YuxiPlugin` 是普通业务对象，以类属性声明入口、辅助 Skill、MCP 和专属工具，只提供 `on_model_call`、`on_tool_call` 两个调用钩子。平台 `PluginMiddleware` 按注册顺序创建实例，注册声明工具并执行统一激活检查；插件的框架同名方法不能新增图节点或 checkpoint 字段，构造函数修改实例工具列表也不改变平台登记的声明集合。平台拥有框架接入与恢复结构，插件拥有业务调用逻辑。

Skill 同步复用既有共享索引、权限和内容投影，读取普通内置目录及已注册插件的配套目录。源码移动保留 Skill ID 和共享路径；重复 slug、未声明的打包内容或同步失败阻止初始化。首次同步写入既有 v2 权限，重复同步保留管理员停用状态。资源发现从注册类的源码位置读取，不依赖运行时工具装配。

### 能力选择、激活与授权

启用表示用户允许智能体使用插件；激活表示模型成功加载了该插件。`PluginLoaderMiddleware` 先披露 ID 和摘要，模型调用 `load_plugin` 后检查入口、辅助说明、连接和工具，成功时通过同一次状态更新返回入口正文并保存 `activated_plugins`。失败保持未激活；Run 内缓存的连接失败在新 Run 中重新检查。

本地专属工具在构图时登记，MCP 工具按需发现；模型请求与实际工具执行都按当前选择、激活状态和权限检查。加载与业务调用处于同一批时，业务调用按该批开始时的激活状态判断。注册阶段拒绝专属工具与通用工具、平台工具及其他插件重名；MCP 加载校验完整目录，包括并行加载间的冲突，再登记来源和激活结果。

入口沿用 Skill 启用状态、访问权及智能体专属绑定。个人 Skill 与插件资源同名时仍作为普通内容，相关插件不可加载。共享辅助 Skill 可被多个插件引用，独立选择的共享内容照常可用；插件激活后披露配套摘要与路径。连接凭据仍由 MCP 管理，启用或激活插件均不授予数据权限，业务 executor 继续复核当前用户授权。

PostgreSQL checkpoint 保存激活状态，消息保存读取的正文；压缩省略正文后可重复加载，工具注册不重复。子会话继承选择并自行激活。Run 清单记录插件 ID、声明和部署版本，供追踪组成；它不承诺重放历史代码。普通 Skill 的读取不改变工具权限，不再保存 `activated_skills`。

### 内置能力与用户入口

`knowledge-base` 组合知识库说明和 `knowledge` MCP；`abridge` 组合设备说明、共享 `chat-widgets` 和设备 MCP。`image-gen`、`deep-research` 保持普通 Skill，通用搜索、沙盒和产物展示能力由智能体工具配置提供。

aBridge 只通过插件进入智能体。MCP 模块集中维护直接选择规则，候选、配置写入及执行授权共同使用；管理目录和内部发现仍保留连接器，其他 MCP 仍可直接选择。设备提示由插件钩子提供，通用 Chatbot 不再拼接设备协议。用户设备管理、登录、委托和每次出站授权仍由 [aBridge 集成](./2026-11-14-abridge-identity.md)承担，不能归入某个智能体的插件开关。

配置页提供插件选择，Skill 编辑页不再编辑运行依赖。输入框保存普通文本 `@plugin:id`，提示模型使用已有 `load_plugin`，不自动激活、不改配置、不混入 MCP 选择。新会话使用 Agent 候选；已有会话使用 Session 冻结选择与当前可访问目录的交集，复用 Thread、Agent 和 APP 授权。旧快照缺少 `plugins` 按空选择处理，不向 Public 协议增加字段。

前端切换会话清空旧目录并忽略迟到响应，失败提供重试。提及与加载标题复用现有图标和目录：会话内从该会话的智能体解析名称，独立工具展示使用当前选中智能体，未知 ID 原样显示。加载卡片沿用默认参数和结果渲染，不增加第二套加载流程。

### 首次生产升级

业务 Schema 从 v2 一次升级到当前 v4，删除 Skill 的三个运行依赖列。知识库入口转换为插件；Agent 和 Session 显式选择 aBridge 或 `mcps=all` 时，在同一次升级中转换为设备插件选择。重复升级跳过当前版本，不重新启用用户关闭的插件。不提供未发布插件版本之间的迁移，也不自动修复本地试验环境的插件配置。

旧自定义 Skill 的 MCP、辅助 Skill 组合先导出为部署声明和配置计划，维护者审阅并随代码发布后应用。只有通用工具依赖的内容仍为普通 Skill，旧通用依赖丢弃，已有工具选择保持原样；内置图像和研究 Skill 保留普通选择及内容。Agent 模板按启用状态和专属绑定转换，Session 按当前用户访问权转换，停用或撤权入口不能成为插件授权。转换入口退出普通 Skill 选择，`skills=all` 展开为明确的插件选择，其他直接 MCP 选择保留。个人 Skill 旧依赖原本不生效，预检要求清理无效字段，不扩大能力。

升级需要维护窗口、数据库及 Skill 文件备份，并排空活动 Run、待消费 Input 和可恢复 Turn。历史 Input、Run 清单、checkpoint 和 Skill 历史版本保持原样；当前内容写入新包，升级后的加载建立插件激活记录。提交前失败回滚数据库并清理新包；提交结果不确定时保留新包，避免删除已提交引用。恢复服务前检查 readiness，回退须配套恢复代码、数据库和文件备份。具体命令由[升级说明](../../../agents/skills-management.md#从运行依赖升级)维护。

## 替代方案

| 替代方案 | 不采用的原因 |
| --- | --- |
| 保留 Skill 依赖，插件只打包 | 说明与能力仍有两套加载规则，依赖事实继续分散 |
| 删除插件层，全部直接选 MCP | 无法一次交付知识库、设备说明和按需工具，也无法解释完整能力开关 |
| 启用即开放全部工具 | 每轮承担全部工具上下文，失去按需披露 |
| 直接继承完整 middleware，再禁止部分接口 | 持续维护钩子禁用清单，图结构与 checkpoint 边界不清晰 |
| 自动扫描插件或新增安装、数据库体系 | 当前没有外部包发现消费者；显式注册可审阅，内容可复用 Skill 同步 |
| aBridge 同时保留直接 MCP 与插件入口 | 关闭插件仍可能开放同一设备能力；把设备管理一并放入插件又会错误绑定用户级资源 |
| 把插件提及解析为自动激活 | 绕过现有加载检查与失败结果，增加第二条激活路径 |
| 为未发布插件形态增加兼容迁移 | 生产无对应数据消费者，增加无效维护面 |

## 后果

首次使用插件增加一次加载调用，开发者需要把代码与入口说明一起发布，API 和 worker 使用同一版本。配置修改只影响新建会话，已有会话沿用快照；撤销数据或设备访问仍由对应授权边界执行。MCP 有其他合法来源时，关闭一个插件只撤去该来源；aBridge 的直接来源被专门关闭。

提及表达意图，不能保证任意模型都遵循指引；可见插件仍可能因连接不可用而加载失败。浏览器展示和 prompt 都不是授权边界。

不兼容插件更新或删除需要检查引用它的智能体、会话和待恢复任务。插件数量增长会带来工具命名、摘要预算和组合测试成本；只在存在真实规模或分发消费者时扩展发现与安装机制。提交结果不确定时允许留下未引用内容目录，以优先保护已提交引用。

## 验证

- 后端 unit 覆盖插件激活、钩子顺序、工具授权与普通 Skill 边界；真实 PostgreSQL/HTTP integration 覆盖提及权限、内容同步、迁移幂等和 checkpoint 恢复。
- 前端 unit 与浏览器脚本覆盖插件提及、配置和加载结果；真实 worker E2E 覆盖知识检索、普通图片 Skill 和 aBridge 跨 Run 激活。
- 实际命令、结果和未验证范围记录在对应提交说明中。平台适配器测试不能替代外部设备、真实企业 OAuth/MCP 账号和全部可选服务的产品验收。
