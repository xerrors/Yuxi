# 重排响应保持输入文档索引对应

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/models/rerank.py

## 问题

`acompute_score` 返回与输入文档等长、同序的分数列表。将部分重排结果排序后只提取分数会压缩该列表，下游 Milvus 按位置配对时发生错配，后续批次也受影响。重复或非法索引、无效分数同样破坏这一契约。

## 决策

`BaseReranker._batch_rerank` 在公共响应边界要求每个输入文档恰好一个结果，index 为范围内的唯一整数，布尔、浮点或字符串索引不满足契约。分数必须存在、非布尔且可转换为有限浮点数；数值字符串继续兼容。全部结果校验成功后按输入索引返回分数。两种提供者共享校验，请求载荷和返回类型保持。

## 替代方案

只排序不校验会保留错配。为缺项填零会把未评分伪装成真实评分。改成索引对象返回值需修改调用方公开契约；本修复保留现有逐文档分数列表。提供者部分返回视为该批不满足全量评分契约，走已有异常路径。

## 后果

畸形响应整批抛出固定错误消息，不回显提供者原始字段。`acompute_score` 继续把失败批的每个文档填为 0.5，后续批次保留自己的位置。normalize=True 时继续执行 sigmoid，降级值约为 0.622459；它不是实际模型相关性。`test_connection` 直接调用批处理，畸形响应返回失败。

兼容端默认只返回 top_n 子集时，该批进入已有降级路径。Dashscope 请求显式要求全部文档，OpenAI-compatible 请求参数保持；本契约不把提供者部分结果定义为逐文档完整评分。改变部分结果、请求参数或降级状态的语义属于独立变更。

## 验证

`backend/test/unit/models/test_rerank.py` 使用两种真实提供者适配器及隔离 HTTP 响应，验证完整乱序和数值字符串、空输入、缺项/重复/非法索引、无效分数、连接检查，以及正常—失败—正常多批次的精确分数与归一化结果。外部提供者连通性和模型质量属于独立探针，不由这些确定性用例证明。
