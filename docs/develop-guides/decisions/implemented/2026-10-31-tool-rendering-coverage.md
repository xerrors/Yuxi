# Mention 浮层与工具动作摘要

状态：implemented
类型：bug-fix
Owner：frontend/src/modules/session/ui/tools/ToolCallRenderer.vue

## 问题

会话用户需要快速识别工具正在执行的动作和对象。部分内置工具缺少可读摘要，直接展示参数或完整回执；重复展示网页、任务结果与历史消息正文会挤占会话空间。Mention 浮层的留白不足，阴影与分组横线过重。

## 决策

### 实现方案

`MessageInputComponent.vue` 使用 12px padding、16px 圆角与弱阴影 token，分组标题靠留白区分，不绘制下划线。浮层保留原有选择与键盘插入行为。

工具入口沿用按名称选择组件的方式。网页抓取展示标题或地址，历史消息展示查询或会话标题与条数，智能体目录展示数量，技能安装展示技能名或来源，改进记录展示动作。它们复用 `BaseToolCall.vue` 的摘要模式，不提供展开正文的交互。技能安装的 producer 使用纯文本回执，专用组件按其固定失败行前缀保留失败提示，不根据任意错误关键词猜测状态。

协作工具展示动作、会话名称和必要状态；存在导航上下文时提供会话入口，会话列表保留可展开的名称列表。查看结果、发送消息和等待工具不重复展示任务输出或消息正文。失败、加载、等待、中断和超时仍由当前工具调用状态决定，完整回执由消息调试面板承载。

任务只调整前端展示，不修改工具执行协议、权限或持久化。未知工具继续使用通用组件，已有文件、检索与图片等专用展示保持原有行为。

## 替代方案

只补充中文工具名仍会留下参数与回执的重复展示。为每种回执增加完整结果面板能覆盖更多字段，但增加阅读负担。采用动作摘要，保留会话跳转、数量和异常状态等直接有用的信息。

## 后果

会话中的工具记录更紧凑；需要诊断字段或完整回执时使用消息调试面板。摘要模式不挂载结果区域，也不保留无效的按钮、展开图标或键盘焦点。协作目录仍提供会话导航，无导航上下文时展示普通名称。
