# 会话引用候选使用会话快照

状态：implemented
类型：bug-fix
Owner：backend/yuxi/modules/agents/services/mentions.py

## 问题

修改智能体的共享 Skill 或知识库选择后，旧会话的引用候选跟随当前智能体，实际运行仍使用会话快照。

## 决策

### 实现方案

Web 通过 `GET /api/mention/resources` 获取会话的插件、共享 Skill 和知识库候选。服务复用会话归属和智能体运行权限校验，用会话快照筛选当前可访问的资源目录。已有会话使用服务结果，草稿使用当前智能体配置。

## 替代方案

向浏览器返回资源选择并在那里筛选，会重复资源权限与配置默认值处理。拆成独立接口会重复会话授权和候选生命周期。

## 后果

已有会话的三类候选共用一次请求和同一套会话授权。服务先归还本地查询占用的连接，再访问共用数据库连接池的 Knowledge MCP。知识库查询超时会记录告警，并保留插件和共享 Skill 候选。历史快照缺少资源字段时沿用运行 Context 的默认值。Web 的候选接口与前端一起更新。
