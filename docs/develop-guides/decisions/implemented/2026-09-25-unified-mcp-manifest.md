# 统一 MCP 创建清单

状态：implemented
类型：feature
Owner：web/src/utils/mcpManifest.js

## 问题

管理页创建 MCP 使用平铺字段，智能体创建使用 `mcpServers` JSON，内置 MCP 初始化使用 Python 字典。相同的连接配置和系统展示信息位于不同层级，新增入口需要分别猜测字段位置。

## 决策

三个入口都使用 `mcpServers` 清单。每个服务的 `type`、`url`、`headers` 和连接超时属于连接配置；Yuxi 的 `name`、`description`、`icon`、`tags` 放在 `extra_data`。已有 PostgreSQL 列继续保存规范化结果；运行时 MCP 客户端只接收连接配置，不接收 `extra_data`。管理页保留字段输入并在提交前使用同一清单解析器；智能体创建直接解析同一结构；内置定义采用同一结构并在初始化时规范化。内置 MCP 初次创建默认禁用，后续同步保留启用状态和禁用工具记录。

现有平铺 MCP 管理 API 保持兼容。清单解析在前端创建边界和后端内置初始化边界执行；不增加数据库列或把 `extra_data` 发送给 MCP 服务端。

## 替代方案

- 把 `extra_data` 原样存入新增 JSON 列：需要迁移与运行时过滤，现有列已拥有这些字段。
- 让每个入口各自转换：能快速满足单点创建，但字段漂移问题仍存在。

## 后果

既有展示字段顶层位置在清单解析时被拒绝，管理员需要按文档把这些字段移入 `extra_data`。直接调用管理 API 的现有平铺请求保持兼容。内置连接定义在代码中使用与页面相同的清单结构，运行时规范化时去掉展示信息，继续保留内置 MCP 的启用状态与禁用工具设置。

## 验证

- 前端 `mcpManifest` unit 验证标准连接字段与 `extra_data` 的映射，并拒绝顶层展示字段、未知 `extra_data` 字段和本地进程配置。
- 后端 MCP service unit 验证内置清单规范化、数据库字段、运行时仅连接字段，以及不支持的展示字段位置；真实 HTTP integration 回读管理员创建的 MCP 元数据、Agent 绑定和普通用户 403。
- 浏览器可控 HTTP 对端验证管理页表单与智能体自动创建各自提交相同的规范化 MCP 请求体，并在管理页回读卡片。创建弹窗的宽屏和 390px 视口均经过截图检查。
- 文档构建通过。规定的后端全量 unit 命令在编辑态构建时因 `yuxi.egg-info` 写权限失败；相关测试使用 `--no-sync` 运行。
