# 对话工作目录分配与缺失后的执行约束

状态：implemented
类型：feature
Owner：backend/yuxi/modules/workspace/services/bindings.py

## 问题

个人空间需要区分自动创建的对话产物和手动整理的项目，并允许用户删除目录后继续查阅原对话。已选 Project 的多个会话共享同一目录，目录删除后的执行约束也必须一致。

## 决策

### 实现方案

未指定 Project 时，路径分配器使用上海日期、首条用户文本和 Project UUID 的前六位，生成 `agents/tasks/YYYY-MM-DD/<前缀>-<短标识>/`。含汉字、无文本或仅有附件使用 `new-chat`，其余取前四个 ASCII 字母数字词，用连字符拼接并截断至 40 字符。Web 内部创建请求提供命名文本并随幂等键重放。带初始输入的公开创建请求取第一条含非空白文本的消息。

Project 创建锁内查找数据库绑定或磁盘占名，遇到占用追加序号。新建会话在提交后续执行可见的绑定、回执和初始 Input 前，以排他方式建立目录。检测到晚到的占用时，创建返回冲突，保留原目录。选中 Project、续聊和改标题都使用已保存的绑定。[历史目录格式](../archived/2026-10-15-project-workdir-date-layout.md)也从绑定读取。

个人空间删除目录后，Project 与 Thread 保留绑定。工作区以 no-follow 方式打开实际目录，缺失、被文件或符号链接替换、或没有目录访问权限时返回 `session_workdir_unavailable`。接受输入、继续队列、转为引导和恢复等待点前校验。自动领取、引导接管与协作等待恢复在目录不可用时保留原 Input 或等待点。已经领取的 Run 由 worker 准入和终态流程收尾。附件准备在标记就绪前复核原件和解析主文件。待消费附件在领取或清理来源前发现正式文件缺失时，从实际存在的临时对象重新准备，目录恢复后自动重试。来源已清理后，若本次新消费的输入所引用的附件文件已缺失，Run 在发出首个模型请求前报告文件不可用。取消只停止执行，随后可显式丢弃仍处于准备中的附件和临时来源。

Web 独立检查目录，历史照常加载，已知缺失时禁用执行操作。历史目录选择器只列出当前可打开的目录。用户可恢复同一路径并重新打开会话。独立保存在个人空间的交付物继续通过来源会话授权，再按实际文件路径读取。详见[沙盒与文件系统](../../../mechanisms/sandbox.md)。

## 替代方案

按纯序号命名会让同日任务的路径依赖创建顺序。保留短标识可区分任务并延续现有分配规则。删除时归档全部关联会话需要协调数据库和文件系统，也无法覆盖其他入口删除目录的情况。

## 后果

英文首条消息的一部分会出现在路径中，分享路径时也可见。创建事务失败后可能留下空目录。删除发生在准备或执行过程中时，后续恢复以实际目录状态为准。

## 验证

- 路径单测和 PostgreSQL 集成用例覆盖命名、碰撞、排他创建、父路径冲突和事务回滚。
- HTTP 用例回读旧目录的历史和文件、新目录命名、删除后的绑定、后续输入拒绝、历史目录候选和独立交付物的下载字节。
- PostgreSQL、MinIO 和 Workdir 用例覆盖接收后删除目录、领取前恢复空目录、只删除解析附件的原件和临时对象先于清理事务消失，回读 Input、附件状态与实际文件字节。真实 worker 用例回读删除就绪文件后的失败终态和空的首次模型请求时间。
- 队列与真实 ARQ 用例回读继续、引导、等待点、取消及已领取 Run 的终态。Chromium 回放检查历史、不可用提示、输入禁用、停止和目录恢复。
- 软配额 E2E 在 4 MiB 配额的独立部署中验证此目录下的真实文件和队列恢复。
