# 知识库原生媒体索引与证据读取

状态：implemented
类型：feature
Owner：backend/yuxi/modules/knowledge/media/service.py

## 问题

图片、录音和视频中的内容需要按原始像素、时序和音轨检索和回读。文本转写可以帮助找资料，原始媒体证据仍由文件和读到的片段标识。

## 决策

### 实现方案

Milvus 知识库以已有文件目录接收原件，以后台作业构建限量衍生片段与向量。作业仓储登记执行权，PostgreSQL 在成功事务中登记活动修订。文件引用、原件校验和向量读回发生在发布检查内。源文件或正文修订变更会使旧资产不可用；文件删除沿用投影回收。

Web 上传可选择图片与音视频模式；管理者选择兼容模型并查看任务状态。管理员可另外启用 PDF 或 Office 文档中提取图片的自动索引，默认关闭。知识 MCP 提供发现、检索和读取工具，在当前用户与所选知识库范围内执行。原件和有界片段的字节访问由原生媒体服务处理，视频帧和音轨分开传给模型，并返回时间码和采样信息。图片引用预览使用同一个授权读取接口。

## 替代方案

将识别文字写入全文索引可以扩大文本召回，但无法复查像素、声学内容和视频时间段。直接发布存储链接会绕过当前读权限和活动修订校验。

## 后果

媒体在后台构建，需要部署已启用的兼容模型。视觉搜索使用向量，音频相关性评分受候选页上限约束。外部调用失败会留下可观察的失败状态。升级需显式建立媒体修订表，详见[部署说明](../../../advanced/deployment.md)。本阶段实现知识库与 MCP 入口，独立 KnowledgeQA 图和对话内专用媒体核验流程另行演进。

## 验证

媒体契约单测验证模型输入、预算和内容格式。隔离服务测试通过 PostgreSQL、MinIO 和 Milvus 核对索引作业、源字节、媒体区间、清单和当前授权，使用固定的兼容模型实现。模型提供商在线结果和真实页面交互还需分别验证。
