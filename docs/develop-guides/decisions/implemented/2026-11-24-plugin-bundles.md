# 业务插件一次启用与专属 MCP

状态：implemented
类型：architecture
Owner：backend/yuxi/modules/extensions/plugins/registry.py

## 问题

同一业务场景的连接定义、操作说明和工具分散。Agent 可把知识库连接当普通 MCP 选择，使其工具先于插件进入模型请求。用户对插件的选择也难以表达一组私有说明的访问范围。

## 决策

### 实现方案

代码插件在类中组合专属连接、工具与入口 Skill，部署者登记一次插件。连接定义提供固定清单，并可指定可用条件与按当前用户装配的委托认证。MCP 服务沿用已有目录同步、工具发现、管理员开关和出站策略。知识库与 aBridge 在 Agent 中分别由所属插件贡献；普通连接仍可直接选择和由插件引用。直接选择连接时，只检查独立连接的可用性。已加载插件的专属连接探测超时时，该连接暂时不可用，普通会话和其他连接仍可使用。对外知识库服务及产品选择器继续使用 Knowledge 域的协议入口与权限校验。

入口 Skill 是私有内容的授权单位。私有说明、脚本及参考文件放在入口包中，复用整包投影和撤权。插件显式引用的共享 Skill 保留自己的访问权。首次模型请求披露插件摘要；加载返回入口正文和文件位置，下一轮模型请求取得工具。

## 替代方案

仅在前端隐藏连接仍允许直接配置、历史会话或其他插件提前引入工具。为每份私有说明新增独立权限或投影会重新引入多次授权。把对外知识服务移入 Agent 插件会让外部客户端依赖 Agent 生命周期。

## 后果

business v5 使用[离线插件升级](../../../agents/skills-management.md#从运行依赖升级)转换旧 Agent 与会话选择，保留历史执行。普通 MCP 的动态全选继续生效。旧连接须有数据库中的内置委托凭据类型或部署者核实过的旧清单作为来源证据。单项 MCP 选择只自动转换为仅提供同一连接、入口 Skill 和默认调用行为的插件。其他连接、配套 Skill、专属工具或自定义调用钩子需要显式启用，v4 已有的设备插件选择继续生效。平台记录内置连接的代码来源，部署移除定义后，旧行无法转成可直接加载的连接。

本决定更新[Knowledge 连接归属](./2026-10-24-knowledge-domain-mcp-ownership.md)与[部署插件资源组织](./2026-11-17-agent-plugins.md)。插件启用只影响 Agent 的能力使用，知识库读取继续受当前用户与会话选库交集约束，aBridge 使用当前用户的设备委托。

## 验证

- Agent 配置与 Public 会话 HTTP 测试回读数据库，验证显式提交专属连接被拒、普通连接能保存、动态全选排除专属连接。
- 知识库 E2E 在真实 API、worker 和 MCP 上回读逐轮工具、查询结果、原文和引用。外部客户端测试使用知识库 Key 经公开协议验证读取与撤权。
- 文件与 PostgreSQL 投影测试读取私有文件并核对撤权后的目录。迁移测试覆盖旧版本选择、同名连接来源、普通 Skill 转为插件入口时的配置冲突、事务回滚与重试。
- aBridge 集成测试覆盖真实登录、设备隔离与撤权。worker 端到端用例使用已开通委托的独立测试账号，核对只读设备列表和跨 Run 激活恢复。
- 配置页通过组件测试及浏览器 DOM 核对选库提示随插件选择变化。
