# 将个人 Cube 的浏览器登记到本人的 aBridge 账户

状态：implemented
类型：feature
Owner：backend/yuxi/modules/extensions/plugins/abridge/managed_browser.py

## 问题

用户在运行环境连接沙盒浏览器后，应该能在自己的 aBridge 设备中找到它。试用实现为浏览器创建另一个主体。即使扩展在线，刷新设备时本人的平台连接也查不到它。聊天还要单独选择浏览器，导致同一用户看到两套设备。

## 决策

### 实现方案

个人登录用户在运行环境点击连接。Yuxi 准备该用户的持久 Cube，使用本人的稳定用户标识向 aBridge 申请浏览器登记，再经来宾私有通道把一次性票据交给客户端。客户端绑定普通浏览器 Device Key。首次连接返回就绪前，核对来宾扩展与 aBridge 登记的设备和在线状态。以后刷新运行环境时，从 aBridge 读取当前 VM 对应设备的在线状态。

aBridge 拥有设备、设备密钥和平台授权。本人首次登记复用普通平台账户的开户规则。已有平台连接的范围和撤销状态由 aBridge 保留。Yuxi 的「我的设备」和启用 aBridge 插件的对话都用现有个人委托查询设备。Cube 休眠时，注册记录保留，运行环境可以重新连接。APP 终端用户继续使用所属 APP 和终端身份的受限授权。

## 替代方案

手工在 aBridge 创建 Browser Device Key 再粘贴到来宾，可以满足独立 Linux 部署，但会让 Cube 用户接触和传递长期密钥。将浏览器登记到另一个主体，再由 Yuxi 合并设备列表或在聊天里切换委托，会绕开个人平台连接的设备和能力选择。

## 后果

新增设备默认出现在授权本人全部设备的平台连接中。用户显式选择了设备或撤销了授权时，由本人在 aBridge 管理可见范围。设备安装和在线状态可在运行环境查看。普通对话、排队和协作继续使用既有输入与会话契约。

本地试用版曾在独立主体下登记浏览器。纠正已有环境时，核对原用户、Cube 和设备后停用旧凭据，保留 VM 和 Chromium Profile，在本人名下重新登记。新登记有新的设备 ID。

## 验证

通过真实 Cube 安装后，在普通 aBridge 设备、Yuxi 设备列表和 aBridge 插件中比对设备 ID，并读取该浏览器中的测试页面。回归用例覆盖普通平台连接的指定设备授权、撤销、跨账号隔离，以及 APP 终端授权。部署和重连步骤见 [aBridge 设备接入](../../../advanced/abridge.md#cube-托管浏览器)。
