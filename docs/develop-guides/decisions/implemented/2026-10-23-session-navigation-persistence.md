# 对话导航与常驻侧栏的刷新恢复

状态：implemented
类型：feature
Owner：frontend/src/modules/session/model/chatUI.js

## 问题

全局对话导航只读取内存中的当前线程，刷新其他页面后无法回到原线程。独立侧栏的常驻展开状态属于布局局部变量，刷新或切页会丢失。普通导航侧栏已有折叠偏好，但不能代替独立对话面板的展开偏好。

## 决策

### 实现方案

ChatUI Store 使用现有 Pinia 持久化入口，按已认证用户 ID 保存导航线程和独立面板常驻状态。ChatThreads Store 在成功改变当前线程时同步导航目标，拒绝的切换不保存；显式新建、归档和删除项目同时清除受影响的持久导航目标。HTTP 403、404、410 确认失效时回到空白页；网络及 5xx 错误保留路由和导航目标，展示现有错误提示。AppLayout 读取已保存目标，临时悬浮状态仍只在内存中。

AppLayout 统一拥有独立面板实例，非对话路由立即隐藏外壳；AgentView 只拥有局部正文占位。面板选中项读取当前路由的 thread_id，避免缓存页面或旧工作区状态影响选中；切页保留常驻偏好，返回对话页或刷新时恢复。显式收起独立面板保存关闭，显式展开或折叠主导航也清除独立面板常驻偏好。普通主导航仍复用原有 sidebarCollapsed 持久化。账号切换只能读取各自偏好，切换账号直接清理内存选择和临时导航展示，不经选择 setter 改写任何账号偏好。异步归档及项目动作在回写导航目标前核对发起账号。偏好不构成线程可见性或授权依据。

## 替代方案

- 直接持久化当前线程：混合当前页面的选择与跨页面导航目标，账号归属也不明确。
- 后端保存 UI 偏好：本需求仅需同一浏览器刷新恢复，引入接口和数据库边界没有必要。

## 后果

偏好仅在当前浏览器中保存，不同步到其他设备。恢复目标与工作区当前选择分开，加载导航偏好不会冒充已加载消息。临时悬浮、项目展开和滚动不跨刷新保存；这些临时状态在两个导航展示间共享。面板的视觉和页面归属由[独立侧栏决策](2026-10-23-session-sidebar-peek.md)说明。

## 验证

- 实际 Pinia 持久化插件 hydration 单测验证：刷新恢复、认证稍后到达、A/B 账号隔离、创建期间拒绝切换、显式清空、项目移除、旧账号归档响应及损坏偏好。只保存侧栏折叠状态与按账号的目标 ID、常驻布尔值，不保存消息或临时展示。
- SessionWorkspace 实际逻辑测试分别向未缓存、已缓存且历史未加载、已缓存且历史已加载的恢复路径注入 403、404、410、503 和网络失败，验证只有确定失效才拒绝路由。已加载缓存返回时重新核对服务端元数据，读取失败结果传回协调器。
- 真实 Vite 浏览器协议 fixture 验证：刷新对话和 Dashboard 后恢复原线程消息及展开状态；显式收起、新建跨刷新保持；账号切换隔离；未缓存和列表已缓存目标均验证 503 保留目标、404 清除目标。固定对话切 Dashboard 的逐帧坐标从首帧稳定在 x=52，且无可见独立面板；另一个浏览器会话完整回归通过。
- `docker compose -p yuxi-container-e2e exec -T frontend pnpm run test:unit`：830 Passed。
- `playwright-cli -s=session-sidebar --raw run-code --filename=frontend/test/browser/sessionSidebar.js`、前端 lint、typecheck/build、工程契约及其 66 项单测：Passed。浏览器使用固定 API 数据，不证明真实后端授权。

本地偏好可能过期或损坏，恢复时只接受预期的 ID 和布尔类型；线程仍通过原 HTTP/页面恢复链路校验。临时网络失败不会作为归档或权限失效的证据。浏览器协议 fixture 只证明前端恢复与展示，不证明真实后端授权。
