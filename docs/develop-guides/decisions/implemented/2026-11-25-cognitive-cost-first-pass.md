# 会话阅读与文档处理入口收敛

状态：implemented
类型：simplification
Owner：frontend/src/modules/session/ui/ThreadTimeline.vue

## 问题

阅读已有 Thread 时，读取入口曾等待输入配置，导致 Agent 详情迟到时路由协调也等待。侧栏点击曾在导航确认前更新 Thread 恢复偏好。知识文件的补解析与入库顺序藏在执行器管理器中，维护者从作业入口难以定位这个文档用例。

## 决策

### 实现方案

在[独立阅读组件](./2026-11-17-thread-session-reading.md)的基础上，ThreadTimeline 完成持久读取和定位后通知工作区。路由等待授权读取及错误分类，工作区以自身当前 Thread 状态准备输入，同一工作区的在途准备合并。Agent 详情就绪前输入禁用，已授权历史仍可读。侧栏发起导航，AppLayout 从已确认的路由更新当前选择和返回偏好。创建期间仍保护草稿交互，已确认的既有 Thread 路由可以装载自己的历史。

[文档处理用例](https://github.com/xerrors/Yuxi/blob/main/backend/yuxi/modules/knowledge/services/document_actions.py)负责解析、按需补解析、入库和分阶段统计刷新。导入、单文件或批量处理与重解析通过该用例执行。Manager 提供运行配置和按类型共享的执行器。文件领取、权限、执行权、持久产物及其发布时序仍由原有边界负责。

## 替代方案

调整方法名可以提示调用目的，但仍使历史依赖输入配置。加入全局协调器会重复路由和已有运行时职责。把整个知识文件流程下沉到具体执行器会使补解析和统计规则分散到各执行器。

## 后果

Agent 详情失败在输入区以已有重试入口处理，路由确认和历史定位有自己的完成结果。路由取消保留原导航目标。知识文件维护者从提交和执行用例追踪到执行器与 repository，可以直接找到补解析判断及统计刷新。

## 验证

- 浏览器回放覆盖 Agent 详情挂起时的可读历史、禁用输入和重复刷新，以及路由取消、创建期间确认既有 Thread、归档深链和返回偏好。恢复读取等待、重复发起输入准备或恢复侧栏预写时，对应观察失败。
- 真实 PostgreSQL/Redis 验证文件处理并发、统计刷新、重解析与作业结果。隔离 Compose 的现有 E2E 回读解析资源、原件、Markdown、索引与图投影，使用固定外部响应。
- 前端会话与导航单测和知识文档用例测试覆盖输入恢复、取消跳转、补解析失败时统计刷新与停止入库。

旧能力不存在：源码、测试及文档搜索核对了 Timeline 的 await 回调、侧栏的选中预写、旧审批入口及无生产写入的加载字段、Manager 的 parse/index 入口。Worker 从以往注册与持久 job 类型调用新用例。

重新引入条件：存在真实读取场景要求输入准备成为前置条件，或出现需要独立文档执行契约的消费者。
