# 就绪探针完成时发布缓存

状态：implemented
类型：bug-fix
Owner：backend/yuxi/modules/system/readiness.py

## 问题

就绪请求可以在共享探针完成前取消。所有请求取消后，探针仍会完成，但没有等待者发布结果或释放在途记录。下次请求能复用已经超过有效期的结果，并从读取时重新开始计时。

## 决策

### 实现方案

共享探针任务在完成时发布结果，以探针完成时间计算缓存有效期，并在退出时释放在途记录。HTTP 请求继续等待受保护的共享任务，并接收结果的独立副本。有效期届满后由下一请求启动新探针。

## 替代方案

让请求完成时清理需要额外追踪所有等待者。让下一请求处理遗留任务仍需要保存探针完成时间。由执行探针的任务一次完成发布和清理即可。

## 后果

客户端取消请求后仍可以复用有效期内的探针结果。探针结果失效后，下一请求重新检查运行依赖，避免将历史可用状态当成当前事实。

## 验证

`uv run --project backend --no-sync --group test pytest backend/test/unit/services/test_readiness_service.py` 覆盖在途复用，并在请求取消后分别读取有效期内和有效期外的结果。恢复旧任务归属后，有效期外的用例依然收到就绪状态，无法看到新出现的 PostgreSQL 故障。
