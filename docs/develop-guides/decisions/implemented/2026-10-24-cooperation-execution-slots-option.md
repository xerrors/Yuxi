# 协作树执行名额与深度配置

状态：implemented
类型：feature
Owner：backend/yuxi/modules/agents/repositories/cooperation.py

## 问题

每棵协作树需要同时限制递归委派深度与执行名额。固定四个执行名额无法适配部署容量，提示词写死名额也会与执行裁决不一致。默认设置需允许一层子会话，并给管理员可配置的并发设置明确上限。

## 决策

### 实现方案

`backend/yuxi/modules/system/options.py` 定义默认值与范围。`max_cooperation_depth` 默认是 1，显式保存的 0 禁止新增子会话。协作服务 `backend/yuxi/modules/agents/services/cooperation.py` 在创建时校验深度，已有幂等结果可继续重放。`max_cooperation_concurrency` 默认是 12，接受 1 到 20 的整数，旧的超限整数按 20 生效。并发最小为 1，确保根会话有资格运行。设置页按相同范围提交完整整数。

`claim_execution_slot` 在树级锁内用调用方数据库会话读取生效配置，裁决同时执行的 Run 数量，包含取消收尾。每个 Run 的协作身份携带 `tree_execution_slots`，供模型规划并行子会话。

## 替代方案

- 固定名额或通过部署环境变量配置，无法由现有设置页在运行期调整。
- 每用户跨树总量上限会引入独立的资源分配规则，当前限制以协作树为单位。
- 一次性改写旧配置可以降低超限值，但会丢失原始配置值。

## 后果

默认值用于尚未保存的字段，已保存的深度和范围内的并发继续生效，旧的超限原值留在数据库。调整深度影响后续新建子会话，调整并发影响下一次执行名额领取。调低名额会暂缓后续领取，等待由补投恢复，已经领取的 Run 继续执行。提示值按每个 Run 首次注入时的配置固定，仅供模型规划。

## 验证

- 后端配置单测覆盖默认值 1 和 12、显式深度 0、并发范围校验及读取旧超限值。
- 真实 HTTP 与 PostgreSQL 集成测试覆盖写入 20、拒绝 21，以及旧原值回读。独立的 PostgreSQL 领取测试将生效上限置为 1，回读成员 Run 暂缓领取的结果。
- 真实 worker E2E 覆盖递归限制、满槽排队和协作恢复，夹具恢复部署原有选项。
- 前端单测和浏览器覆盖设置页默认值、并发步进上限，以及非法输入不提交。
