# Embedding 响应必须与输入逐条对应

状态：implemented
类型：bug-fix
Owner：backend/yuxi/modules/models/embed.py

## 问题

向量库按位置关联文本与向量，语义切分也按位置关联句子与聚类标签。供应商返回部分结果或乱序结果时，仅提取 `data[*].embedding` 会造成错配；将 `null` 当作索引空槽再过滤，还会减少直接 `encode` / `aencode` 返回的向量数量，让语义切分静默丢句，并掩盖重复索引。

## 决策

### 实现方案

[响应解析](https://github.com/xerrors/Yuxi/blob/main/backend/yuxi/modules/models/embed.py)拥有逐条对应的校验。同步、异步 HTTP 入口传入请求条数（字符串计一条），解析函数拒绝条数不符、缺少向量或向量为 `null` 的响应。供应商提供索引时，使用索引到向量的映射独立检查整数类型、范围、重复及混合缺失，再按索引返回；不使用向量内容判断槽位是否占用，也不通过过滤修补结果。

无索引响应保持供应商顺序；所有索引为空时保留无索引兼容行为。批处理入口在累加前复用数量检查，防止子类返回部分批次。任何不满足约束的批次都抛出 `ValueError`，调用方拿不到部分结果。

这是模型响应边界内的完整修复，不新增状态、依赖、配置或待裁决方案，因此直接记录为 implemented。HTTP 重试策略、持久化顺序和事务边界保持不变。

## 替代方案

- 填零向量或截断结果：隐藏缺项并继续造成错配，不采用。
- 在每个调用方校验：无法统一处理供应商索引，也遗漏直接调用路径，不采用。
- 用 `None` 槽位同时判断重复与过滤结果：混淆供应商数据与索引占用状态，不采用。

## 后果

畸形响应明确失败；合法的乱序索引按输入顺序归位，无索引响应继续按响应顺序处理。数量正确但向量内容错误、维度或模型质量不在本契约范围内；不会修复已经写入的历史数据。

## 验证

[回归测试](https://github.com/xerrors/Yuxi/blob/main/backend/test/unit/models/test_embed_alignment.py)在 HTTP 边界替换供应商响应，覆盖同步和异步直接调用的缺项、多项、空向量、空向量加重复索引、混合索引，以及正常归位、无索引、字符串和空输入。批处理测试验证首批成功后，后续缺项仍整批失败；索引测试覆盖负数、越界及非整数。

运行命令：`cd backend && uv run --no-sync --group test pytest test/unit/models/test_embed_alignment.py -q`。实际执行结果随 PR 记录；真实供应商调用与数据存储链路不由这些单元测试证明。
