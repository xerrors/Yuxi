# 文件元数据管理与检索过滤

状态：implemented
类型：feature
Owner：backend/yuxi/modules/knowledge/services/metadata.py

## 问题

同一知识库的资料具有不同适用范围，语义相近不代表适用于同一次查询。用户需要为新旧文件按需定义、填写和修改字段，并在检索前限定范围；新增同类型字段不应修改代码或重新上传原件。字段定义、属性管理与过滤属于知识域，具体业务的地区、资格判断和追问规则属于使用者配置。

目标是完成字段管理、文件属性单个及批量修改、导入属性、MCP 字段发现和结构化过滤。非目标是政策判断引擎、自动生成标签、逐 Chunk 手工属性覆盖或跨重新分块重绑。文件级过滤要求入库文档的适用范围一致；一份原件内部混合范围时需先整理内容，不能将整篇标多个范围冒充章节隔离。

## 决策

### 实现方案

知识库保存字段定义，文件保存独立 JSONB `attributes`；均不混入解析配置或来源字段。字段 key 稳定，显示名称与说明可修改；类型创建后固定。文本、数字、布尔、日期、单选和多选字段按类型验证；删除仍有值的字段或选项拒绝，使用者先显式清理。普通值不接受 null，清除通过 unset 表达。新知识库和文件默认没有自定义字段或属性。

管理用例复用知识库写锁及现有权限解析，同库批量 set/unset 在单个事务中提交，只修改声明字段。字段定义变更、文件属性更新和导入遵循同一验证规则；导入携带属性时纳入请求指纹。指纹复用不会改写既有属性；提交的属性有差异时返回该文件的冲突结果。元数据修改不触发解析或索引，重建保留文件属性。知识 Schema 升级为 v3，提供独立、幂等的 v2 到 v3 维护命令，运行进程仍只检查版本，不自动迁移。

过滤表达式包含有类型的条件和有界 AND/OR 分组，支持等于、不等于、数值/日期比较、多选任一/全部包含、是否设置。缺失值不命中普通比较，包括否定比较；未传过滤与有效条件匹配空集严格区分。未知字段、错误类型、非法操作符及过深表达式明确拒绝。

字段与条件由 knowledge service 校验，repository 在查询有效文件和 active generation 的同一 SQL 中执行属性条件，替换现有唯一检索消费者使用的活跃代次查询。Milvus 对匹配的 file_id 和 generation 做检索前过滤，空候选不退回全库。向量、BM25、混合及图谱候选复用范围；图谱在最终候选截断前排除范围外文件，返回时继续复核，不承诺超出现有遍历边界的召回充分性。候选规模明确校验，不能继承文件名 helper 的 10,000 条静默截断。

Knowledge MCP 提供按知识库获取当前字段定义的只读能力，查询工具接受通用过滤结构；Public HTTP 维持既有请求模型。管理界面和检索测试走 Web 业务入口。检索结果在独立 attributes 命名空间返回文件属性，原文窗口、引用身份及权限契约保持由既有实现拥有。外接知识库未实现属性过滤时明确拒绝。Agent 通过字段发现提交条件，继续使用现有 ask_user_question；模型选择条件及识别信息不足不升级为通用后端保证。

前端沿用现有知识库设置、文件详情、批量操作和检索测试表单，提供字段定义、属性编辑和条件分组；不引入新的全局设计系统。所有保存以服务端返回事实为准。

## 替代方案

将业务属性复制到 Milvus JSON 同样可过滤，但增加集合升级、每文件 Chunk 投影和同步一致性维护，当前没有测量证据要求承担这些成本。按业务字段组合拆知识库会重复资料与权限配置，不能满足同库可选字段的需求。

## 后果

PostgreSQL 同时拥有字段定义、文件属性和范围条件；不存在第二份 Chunk 属性投影，修改属性后不需要等待向量同步。来源回读会在当次 PostgreSQL 语句快照内复核条件；这不构成覆盖重排和 HTTP 发送全过程的线性一致性保证。普通查询继续按 Chunk 计算相关性，文件属性只决定候选范围。

每库最多 64 个字段，单文件属性 JSON 最多 64 KiB，过滤树最多 50 个节点、5 层；候选文件表达式超过 2 MiB 时明确失败。长候选列表仍有数据库、序列化和 Milvus 参数成本，后续扩展应以真实容量测量为依据。字段缺失不代表业务通用；地区、政策资格和追问条件属于具体知识库及 Agent 配置。文件级元数据不解决同一文档内部的适用范围混合。

Schema v3 是显式升级要求。v1 的目录迁移使用历史表映射，不依赖新版属性列，因此保留 v1 → v2 → v3 的升级路径。维护步骤由[部署参考](../../../advanced/deployment.md)拥有；此次验证在隔离槽位完成，未迁移原运行环境的数据。

## 验证

- 后端定向单测覆盖字段和值类型、空结果、过滤预算、MCP 多库契约和 Milvus 候选范围。
- 隔离 PostgreSQL 迁移集成测试覆盖 v2 旧库、目录迁移链、重复执行、错误列类型的事务回滚。
- 前端定向单测覆盖字段与过滤操作和现有文件详情入口。
- 系统测试使用真实 HTTP、PostgreSQL、Milvus 和 Neo4j 验证重复导入属性冲突、图谱候选截断和大范围检索。Worker 用例使用确定性模型重放，证明插件加载后能够发现字段和按属性检索。
