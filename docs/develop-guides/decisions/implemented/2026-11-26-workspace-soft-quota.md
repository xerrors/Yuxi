# Workspace 个人用量与任务准入

状态：implemented
类型：feature
Owner：backend/yuxi/modules/workspace/services/quota.py

## 问题

网页、worker 和沙盒都可写入个人目录。部署需要在保留现有数据卷和活跃任务的条件下，在空间满时暂停新的文件上传和用户任务。

## 决策

### 实现方案

Workspace 在宿主侧统计个人目录的已分配块，PostgreSQL 为每个逻辑 UID 保存最新成功观测。worker 启动后立即巡检，之后每隔五分钟尝试，只扫描有待处理标记的 UID，未扫描及最久未尝试的用户优先，每个目录遍历限时四分钟。页面、文件上传与 Agent 调度共用最近一次成功的用量快照。首次测量前允许上传和启动任务，扫描失败时保留已有快照并向页面报告失败。

宿主 Workspace 文件变更及沙盒创建、恢复前，在共享卷的服务目录按逻辑 UID 登记标记。一份待测标记可合并多次写入。巡检领取这一代后，后续写入可以登记下一代。Cube 使用持久化环境状态，Container 通过 runner 读取尚未回收的容器，包含独立 Skill 获取容器和已退出但仍待清理的容器。扫描开始时仍可能写入的沙盒保留标记。确认休眠或回收后，worker 成功落库再确认该次领取的代次。测量或落库失败时重试。进行中的宿主写入、扫描期间新增的变更及暂时无法确认的沙盒状态继续待测。巡检通过共享 Linux 卷的文件锁串行执行，计量不占 ARQ 作业槽，数据库连接只用于短读写。

API 和 worker 在启动时校验软配额为正整数。非法配置阻止 API 接流量及 worker 领取输入。

达到额度时，个人空间、会话文件浏览器和聊天附件的上传入口拒绝新文件。调度器在领取用户输入并创建新顶层 Turn 前检查快照，待启动的输入保留在原队列。已运行任务可以调用工具、保存产物或从等待点恢复，用户仍可编辑文件、安装 Skill 和清理空间。运行中的任务发起协作时，协作输入在原队列中等待轮次；到达队头即可派发，如果前面有因配额暂缓的用户输入，则一同等待。后续巡检确认用量低于额度后，调度器按原序派发，并继续尊重手动暂停和归档。

## 替代方案

目录项目配额能给所有挂载写入提供硬上限，需要部署方准备支持配额的卷。按 API 写入字节累加会遗漏沙盒命令产生的文件。逐次写入扫描会将用户操作延迟绑定到目录大小。

## 后果

存量库先按最近文件迁移进入 business 7 / knowledge 2，再离线升级到 business 8 / knowledge 2。用量迁移保留已有的最近文件记录。默认额度为 10 GiB。两个成功快照之间及活跃 Turn 仍可增长目录，超量字节数无固定上界。已删除但仍由进程打开的文件无法通过目录遍历计量。Workspace 统计不计 Cube 私有磁盘及 MinIO 对象。自定义沙盒 UID/GID 若导致 worker 无法遍历共享目录，扫描会失败，并继续使用上一次成功快照。推进范围以应用内写入与部署管理的沙盒生命周期为准。存量快照保留，部署不发起全量扫描。升级或直接从宿主改动文件时，按[部署指引](../../../advanced/deployment.md)处理。

7→8 升级前检查最近文件表。启动和版本 8 的迁移重跑同时检查最近文件表与用量表，避免接管同编号的其他开发分支数据库。

- 启动回归覆盖 API 和 worker 的零额度及非整数配置，验证非法值在数据库装配前被拒绝。

- 目录计量测试 `backend/test/unit/workspace/test_quota.py` 对照分配块，覆盖稀疏文件、硬链接和软链接。
- 标记测试验证重复写入合并、领取后改动保留、无变更退出巡检。真实 Cube 集成测试验证创建、活跃期间连续更新、休眠后的失败重试和末次成功清除，以及恢复后重新登记。真实 Docker 测试查验运行中及待回收容器的 UID 保留。
- 迁移测试 `backend/test/integration/services/test_schema_migration_version.py` 回读已有用户的打开历史、用量快照、域版本与幂等升级结果。
