# 协作默认深度与并发上限

状态：implemented
类型：feature
Owner：backend/yuxi/modules/system/options.py

## 问题

协作设置需要默认允许一层子会话，并提高每棵协作树的默认并发。管理员可配置的并发需要明确上限。

## 决策

### 实现方案

系统选项的默认深度为 1，默认并发为 12，可配置并发范围为 1 到 20。配置更新通过 Option 校验，配置读取将旧的超限整数按 20 生效。设置页的数字输入和说明使用相同范围，现有协作服务与 Run 名额领取读取生效配置。

本决定更新[协作树执行名额](2026-10-24-cooperation-execution-slots-option.md)的默认值与范围，以及 [GUI 缺陷修复](2026-10-12-gui-report-remaining-defects.md)中的协作深度默认值。

## 替代方案

一次性改写旧配置也能让超限值降到 20，但会丢失原始值。

## 后果

新默认值用于未保存的字段。已保存的深度和范围内的并发继续生效，旧的超限并发从下一次 Run 领取起按 20 生效，数据库保留原值，已领取的 Run 继续执行。

## 验证

- 配置单测验证未设置字段得到深度 1 与并发 12，显式配置深度 0 和并发 1 仍生效，并覆盖新配置拒绝 21 与旧配置读为 20。
- 真实 HTTP 与 PostgreSQL 集成测试验证写入 20、拒绝 21，并回读原始值与旧配置的生效值。
- 隔离 Compose 的真实 worker E2E 显式配置深度和执行名额，验证递归限制、满槽排队与协作恢复。夹具结束后恢复原始配置字段，缺失项继续使用系统默认值。
- 前端单测验证控件默认值和输入上限，覆盖 20 可以提交、21 被拒绝。
- 浏览器验证设置页默认显示 1 和 12，并发步进在 20 停止。
