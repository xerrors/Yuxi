# 部门与用户管理批量删除

状态：implemented
类型：feature
Owner：frontend/src/modules/settings/model/confirmManagementBatchDeletion.js

## 问题

管理员需要明确勾选要删除的用户或部门，确认一次并查看各项结果。用户列表按页加载，多选目标可能分布在不同页。

## 决策

### 实现方案

用户管理在当前筛选范围内保留跨页勾选，并显示累计数量。表头复选框处理当前页，清空选择处理各页。改变筛选或登录凭据会清空用户选择。读取期间或读取失败时，用户和部门表格禁用勾选及批量删除。重新读取页面时剔除已知无法删除的记录，单独删除成功时移除对应勾选。部门表格沿用本页勾选。两个面板都复用行内删除的保护条件，批量确认固定选中的 ID，身份接口逐项授权并独立提交。执行期间若登录凭据变化，前端停止提交剩余记录。

## 替代方案

- 服务端新增批量端点可以提供单请求或整批事务语义，需要新增公开契约。当前交互可以通过单项接口完成。
- 并行发起单项请求可以缩短等待时间，但会同时争用身份写入事务与锁。串行执行复用各项当前的事务边界。
- 翻页时清空勾选会迫使管理员按页重复确认，无法完成跨页批量操作。

## 后果

单项操作独立提交，批次允许部分完成。前端用 Message 汇报已确认的删除数量和未确认的结果。用户列表只加载当前页，其他页的记录可能在请求之间发生变化。后端使用当前状态执行授权。用户删除结果未确认时保留对应勾选，管理员可以逐页核查或清空。部门删除会迁移成员并吊销该部门的 API Key。

## 验证

`frontend/test/browser/managementBatchDeletion.js` 在运行中的构建页面使用合成 HTTP 数据，核对两页选择合计、当前页全选和清空、读失败禁用、旧分页响应失效，以及跨页删除和单独删除发送的 ID。用例还覆盖默认聚焦取消、受保护的行、部门部分失败和更换凭据后停止发送请求。
