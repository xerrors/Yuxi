# 知识库 URL 导入失败原因

状态：implemented
类型：bug-fix
Owner：backend/yuxi/modules/knowledge/utils/url_fetcher.py

## 问题

知识库 URL 导入在白名单未配置时返回 400 字符串 detail，网页请求层按错误信息边界把它替换为“请求参数错误”。管理员无法区分未启用、域名不允许和抓取失败，也容易误认为 Agent 的网页读取供应商配置控制了导入。

## 决策

### 实现方案

抓取器复用现有 `InvalidOperationError` 和业务 code/message detail，保留 HTTP 400。URL 校验器拥有可公开的中文拒绝原因，抓取器拥有重定向、类型、大小和抓取失败文案；网络及未知异常只产生固定公开消息，原始异常留在服务端日志。现有 API 领域异常适配器、网页请求层和文件添加弹窗完成传递与展示，不增加 URL 专属的前端请求规则。

目标是页面展示可行动的失败原因，并继续拒绝未授权域名和不安全地址。不调整部署白名单、SSRF 策略、网页读取供应商或成功暂存流程。

## 替代方案

全局透传 400 字符串会放开其他接口的内部错误；在请求层按路径建立例外会复制知识域规则。修改白名单可启用特定来源，但不能修复失败原因被隐藏的问题。

## 后果

400 的 detail 从字符串变为现有业务对象格式，网页客户端已支持此契约。允许域名通过[安全设置中的 URL 导入配置](./2026-11-10-knowledge-url-import-options.md)维护，未保存时沿用部署环境；网页供应商配置不会启用知识库抓取。

## 验证

- `test/unit/knowledge/test_url_fetcher.py` 保留白名单、DNS 钉扎和私网防护验证，受限重定向、缺少跳转地址、非 HTML 与超限内容的拒绝案例通过。
- 前端 `test/unit/api_boundary.test.js` 共 22 项通过，证明 URL API 保留公开业务消息并移除内部上下文。`test/browser/knowledgeUrlImport.js` 使用固定 HTTP 响应验证真实弹窗的三类错误、失败条目不可入库，以及明暗主题和 768px 宽度下的展示。
- 前端 lint、工程契约及其 56 项测试、文档构建通过。容器缺少仓库根目录文件的配置测试由宿主配置测试补足，容器跳过不能作为部署契约通过的证据。
