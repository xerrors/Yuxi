# 显式智能体资源选择

状态：implemented
类型：feature
Owner：backend/package/yuxi/agents/context.py

## 问题

资源配置使用 null 表达全部，子智能体还使用空数组表达全部，调用方无法一致地区分全部、禁用和固定选择。配置意图需要在保存、界面展示与运行权限过滤之间保持一致。

## 决策

### 实现方案

Context 的资源选择使用 `Literal["all"] | list[str]`，空数组统一表示不选择。工具、知识库、Skill 默认 all，子智能体默认 ["general-purpose"]，MCP 和预加载 Skill 默认空数组，均支持显式 all；预加载范围来自当前 Agent 已启用且可访问的 Skill，统一规则的取舍见[预加载协议简化](./2026-09-27-unified-preload-selection.md)。创建时省略字段使用字段默认值，局部更新省略字段保留已有值。repository 校验写入形状并保留既有隐藏引用，运行准备阶段展开 all 并过滤当前用户可用资源。前端提供独立全部模式，逐项勾选保留数组意图；CLI 将空数组显示为“无”、all 显示为“全部可用（含新增）”。子智能体中间件只消费已解析的允许列表，空列表不注册子智能体工具。个人 Skill 安装只扩充固定列表，全部模式保持原配置。资源权限、Skill 依赖加载和 Run 调度维持各自 Owner。

storage-migrator 将 business schema 升至 9，在同一事务迁移 Agent 配置并记录版本。旧工具、知识库、Skill、子智能体 null 以及子智能体空数组转为 all；旧 MCP 和预加载 null 转为空数组。省略字段和固定列表保持原样。版本 gate 防止再次把新空数组解释成全部，新写入拒绝 null。SQL 显式转换 JSONB，兼容当前 JSON 列和历史 JSONB 列。

## 替代方案

保留 null 会继续混淆缺省与全部；增加 mode/items 对象对当前三态没有额外价值；保存时展开 all 无法覆盖后续新增资源。迁移时只改数据再单独记录版本会留下重试窗口，可能把新协议的空数组扩大为全部，因此二者同事务提交。

## 后果

省略子智能体配置时仅启用通用任务，避免新增专用角色自动进入默认范围。已有显式 all、空数组和固定列表保持原意；深度研究等预设的显式角色选择保持不变。通用任务不可见时得到空列表，不回退到其他角色。

`"all"` 保存动态范围，固定数组保存显式引用；运行时可见性取决于执行用户。新协议拒绝旧客户端提交 null，升级先停止旧 API 和 worker 写入并运行迁移器。回退需要恢复升级前数据库备份，不能只回退代码。前端隐藏没有候选项且没有历史固定选择的资源分组，减少空区块；隐藏不改写已保存的 all 或空数组，后续出现候选项时自动显示。已有不可见固定选择保留提示和清空入口。

## 验证

- Passed：Context 与 repository 单测验证动态新增、空子智能体列表、非法值拒绝、隐藏引用保留和 all 不授予越权新增引用的能力。
- Passed：真实 PostgreSQL integration 验证 JSON/JSONB 迁移结果、版本写入失败后的整体回滚，以及再次执行时保留新空数组。
- Passed：真实 HTTP integration 保存并回读 all/空数组，拒绝 null、未知字符串和混合数组后数据库保持原值，省略字段保留已有值。隔离库内置 Skill fixture 显式使用 v2 权限格式；默认初始化生成旧权限格式的问题不属于本决定。
- Passed：真实 Chatbot 中间件装配的单测验证空列表及权限过滤后为空都不注册子智能体工具，all 仍注册；个人 Skill 安装保留 all，CLI 区分全部与禁用。
- Passed：Web 选择逻辑验证 all 跟随新增、手动勾满仍为固定数组；浏览器保存空子智能体列表后从 PostgreSQL 回读确认。
- Not run：完整 worker/模型 E2E；隔离测试仅启动 API、PostgreSQL、Redis 和 Web，资源实际执行依赖仍由既有 Run/Skill 链路拥有。
