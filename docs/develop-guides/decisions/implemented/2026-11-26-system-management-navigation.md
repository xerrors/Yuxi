# 系统管理导航与旧链接迁移

状态：implemented
类型：feature
Owner：frontend/src/pages/SystemManageView.vue

## 问题

用户需要从侧栏管理模型供应商、API 接入、用户和部门，同时从现有「智能体」入口配置智能体与定时任务。API Key 操作需要搭配 APP 接入信息，已有书签会携带标签、目标智能体和锚点。

## 决策

侧栏提供「智能体」和「系统管理」。智能体页承担智能体配置和定时任务。系统管理提供「模型供应商」「API 集成」「用户管理」「部门管理」「系统概览」「智能体反馈」同级标签。API Key 管理对所有登录用户开放，模型供应商和用户管理沿用管理员权限，部门管理、APP 接入概览、系统概览和智能体反馈对超级管理员开放。

### 实现方案

`frontend/src/app/router/index.js` 将 `/agent-manage` 的模型供应商和 API 集成书签迁移到 `/system-manage`，保留其他查询参数和锚点。智能体配置和定时任务在 `/agent-manage` 打开。系统管理页使用其实际提供的标签，按角色装配面板，在用户管理和部门管理之间切换时保留已打开的筛选状态。API Key 写入成功后，接入概览回读 APP 数据，并丢弃较早发出的请求结果。统计和接入说明见[API 集成入口与知识库 MCP 接入说明](./2026-10-28-api-integration-surface.md)。

旧 `/dashboard` 书签迁移到系统概览，旧反馈链接迁移到智能体反馈，并保留其他参数和锚点。两个面板共用系统管理页头。

## 替代方案

- 将智能体配置一起迁入系统管理会改变常用入口，原智能体页也无法同时承载配置和定时任务。
- 在同一标签内嵌用户与部门切换会增加一层导航，独立标签让两项管理从页头直接打开。
- 将系统概览和智能体反馈放在「数据总览」下会形成两层标签，两个独立标签可从页头直接打开。

## 后果

设置弹窗保留账户、设备、运行环境和其余系统设置。现有数据继续由各业务 API 管理，前端升级无需执行数据库迁移。

## 验证

在运行页面用 Playwright 执行 `frontend/test/browser/systemManagement.js`。检查两个侧栏入口、旧书签的参数与智能体编辑表单、各角色的页面与请求、Key 创建与迟到的概览响应、用户与部门标签的键盘切换和筛选保留。浏览器覆盖 1440、1024 和 768 像素宽度，管理 API 使用合成响应。

`frontend/test/browser/apiIntegrationSurfaces.js` 核对知识库 MCP 的新链接、统计错误恢复和实际服务的 OpenAPI 端点。`frontend/test/browser/sessionSidebar.js` 验证离开系统管理后回到原对话时仍保留草稿。
