# MinIO 镜像改为仓库内构建

状态：archived
类型：architecture
Owner：docker/minio/Dockerfile

## 问题

Compose 原先依赖的 MinIO 镜像停止公开分发。新部署无法拉取镜像，CI 也因此无法启动测试拓扑。对应版本的官方 GitHub Release 仍提供按架构分发的二进制和校验值。

## 决策

Compose 从仓库的 Dockerfile 构建 MinIO。原替换版本使用与退役镜像相同的 MinIO 二进制，并在构建时校验各架构的 SHA-256。离线镜像导出使用 Compose 解析出的镜像名，在打包前完成构建。

## 替代方案

维持私有镜像来源会引入部署与 CI 凭据。使用第三方重打包镜像无法确认二进制来源。更换对象存储实现会引入数据卷迁移。

## 后果

有网络的环境负责下载、校验和构建，离线环境继续使用导出的镜像。运行时镜像的版本、构建命令与再分发说明由[部署指南](../../../advanced/deployment.md)维护。

## 验证

原替换验证比对了 amd64 二进制的校验值与版本，并用既有数据卷回读对象。arm64 验证覆盖构建和校验。后续升级由当前 Dockerfile 固定各架构的校验值。
