### Agent 对话 LLM 调用迁移 Worker 方案
- 深度分析了 `/chat/agent` 和 `/chat/agent/sync` 端点为什么 LLM 在 API 节点执行而非 Worker 节点
- 根本原因：两个端点直接在 API 进程中调用 `stream_agent_chat()` / `agent_chat()`，LangGraph 图执行和 LLM 调用全部在 api-dev 容器中
- Worker 的 `process_agent_run` 内部调用的是同一个 `stream_agent_chat()`，接口输出格式完全兼容，不需要改 LLM 调用逻辑
- 当前存在两条路径：Chat 路径（API 进程）和 Runs 路径（Worker 进程），`VITE_USE_RUNS_API=true` 时前端走 Runs 路径
- 设计了 Relay 模式改造方案：API 创建 Run 入队 Worker → 从 Redis Stream 消费 chunk → 原样转发给调用方
- 已写入完整方案到 `docs/vibe/2026-05-25-agent-chat-worker-offload-design.md`，包含架构图、伪代码、分步实施计划、风险评估、验收 checklist
